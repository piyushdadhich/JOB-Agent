EXTRACTION RULES:

1. Roles: extract every distinct role from the inventory. Each role
   gets a unique snake_case id derived from employer + key descriptor
   + end year (e.g. "testco_payments_2024",
   "cognizant_discover_2023"). If the role is current, use the
   current year.

2. Function field: ONE sentence describing what the role actually
   did, NOT the title. Example: "Validate land acquisition payments
   under Ontario Expropriations Act before fund release." NOT
   "Payments Officer."

3. Skill clusters: snake_case tags grouping related capabilities.
   Use existing tags where possible; introduce new ones only when
   needed. Avoid overly generic tags ("management", "communication").
   Examples: "payments_operations", "expropriations_compliance",
   "offshore_delivery_leadership", "sap_otc_implementation".

4. Evidence phrases: 3-7 phrases per role, paraphrased or quoted
   from the inventory, that ground each cluster. These are what a
   future evaluator will use to verify a match.

5. Outcomes: measurable accomplishments. Numbers, percentages,
   timeframes. Example: "Caught $50K legal fees overpayment before
   release." NOT "Caught errors in payment files." If the inventory
   does not state measurable outcomes for a role, output an empty
   list []. Do NOT invent metrics.

6. Cultural signals: tags about the work environment.
   Examples: "matrix_organization", "regulated_industry",
   "founder_proximity", "offshore_team_lead", "sole_implementer".

7. Red flags: lessons learned, things that didn't work, environments
   to avoid. Example: "matrix_no_delivery_ownership" (recognized
   from Acme Corp MegaBank declined-reassignment situation). If a role
   has no red flags in the inventory, output an empty list [].

8. Transferable skill clusters: cross-role groupings. For each, list
   the role IDs that demonstrate it. Every role id referenced here
   must be present in the roles array; do not invent ids.

9. Trajectory: based on the candidate's most senior recent roles
   (typically the last 3-5 years of substantive work), what's the
   advance, lateral, and avoid pattern. Recency and seniority are
   both signals; weight seniority slightly higher when they
   conflict.

10. Hard exclusions and geography: copy verbatim from any explicit
    statement in the inventory. If the inventory does not state
    hard exclusions, output an empty list []. Same for geography.

11. Red flags should be patterns or anti-patterns, NOT specific
    company names. Example: "matrix_no_delivery_ownership" (good --
    describes a pattern). NOT "avoid_MegaBank_engagement" (bad --
    names a specific company). The hard_exclusions field is the
    correct place for company-specific exclusions; red_flags is
    for environmental/cultural patterns to recognize across
    employers.
